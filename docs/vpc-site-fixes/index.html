1

The LocalBusiness schema block has two typos that may void it

5 minutes Two-word edit Fully reversible
What we've identified

The homepage carries three blocks of structured data. Two of them are clean. The third is the one that states the company name, phone number and street address together, and it has two problems in its first two lines.

The context is written as https://www.schema.org. The vocabulary lives at https://schema.org, without the www. And the type is written as localbusiness in lowercase, where schema.org type names are case sensitive and the defined type is LocalBusiness.

Either one on its own is enough for a parser to fail to recognize the block. We have not asserted what Google does with it, because Google's own tool will tell you that directly. See the checking step.

How to verify it
  1. Open Google's Rich Results Test, paste in https://www.vpcfiberglass.com/ and run it. Look at what it detects. If LocalBusiness is not in the detected list while the other blocks are, that is the finding.
  2. Cross-check on validator.schema.org with the same URL. It is more literal about the vocabulary than Google is and will show the unrecognized type.
  3. To see the source yourself: open the homepage, right-click and choose View Page Source, then search the page for www.schema.org. It appears once, in the block in question.
Why it matters

This block is the only place on the site where the name, phone and address are stated together in a form built for machines to read. When an AI assistant or a search engine wants to confirm that VPC is a real company at a real address with a real phone number, this is the record it reads. Two typos is a low price for having it work.

What to do

Two strings change. Nothing else in the block needs touching.

Currently
{
"@context": "https://www.schema.org",
"@type": "localbusiness",
"name": "Virtual Polymer Compounds, LLC",
"telephone": "585-735-9668",
...
Should be
{
"@context": "https://schema.org",
"@type": "LocalBusiness",
"name": "Virtual Polymer Compounds, LLC",
"telephone": "585-735-9668",
...

This block is hand-placed rather than generated by Rank Math, so it will not be in the plugin's settings. The fastest way to find it is to search the theme files or your header-injection plugin for the string priceRange or www.schema.org. Likely homes are the Divi theme header, a Divi code module on the homepage, or whatever plugin injects header scripts.

After saving, re-run the Rich Results Test on the live URL to confirm the type is picked up.

2

No social share image, so every shared link renders as plain text

10 minutes Settings only Fully reversible
What we've identified

The homepage has most of the Open Graph tags in place: og:title, og:description, og:url, og:type, og:site_name, og:locale. The one that is absent is og:image. There are also no Twitter card tags at all.

The practical effect is that when anyone pastes a vpcfiberglass.com link into LinkedIn, Teams, Outlook, Slack or a text message, it renders as a text box with no picture.

How to verify it
  1. The fastest check needs no tools. Paste https://www.vpcfiberglass.com/ into a Teams or LinkedIn message box, wait for the preview to build, and look at whether an image appears. Do not send it.
  2. Or open the homepage, View Page Source, and search for og:image. You will find og:title and og:description but no image tag.
  3. Or run the URL through a preview debugger such as opengraph.xyz, which shows exactly what each platform will render.
Why it matters

VPC's sales cycle runs through email and increasingly through Teams. A link to a product page that arrives as a bare grey box is a weaker artifact than the same link with a photograph of the actual product on it, and the difference is one settings field.

What to do
  • In WordPress, go to Rank Math → Titles & Meta → Global Meta and set a default Open Graph image. That one setting covers every page that does not specify its own.
  • Size it 1200 × 630 pixels. A photograph of finished FRP work will carry further than a logo on white, since the logo will already appear next to it in most previews.
  • For pages worth a specific image, the per-page override is in the Rank Math box on the edit screen, under the Social tab.
  • Re-run the preview debugger afterwards. Some platforms cache the old result, so use the debugger's refresh or scrape button rather than assuming it did not work.
3

Four near-identical Enduro enclosure pages, each pointing at itself

20 minutes One judgment call Reversible
What we've identified

Four live URLs carry the same page title, Enduro Standard Equipment Enclosure:

  • /enduro-standard-equipment-enclosure/
  • /enduro-standard-equipment-enclosure-2/
  • /enduro-standard-equipment-enclosure-3/
  • /vpc-case-studies/enduro-standard-equipment-enclosure-5/

All four return 200 and all four appear in the sitemaps. More to the point, each one has a canonical tag pointing at itself, so none of them defers to a primary version. As far as a search engine can tell, these are four separate pages competing with each other for the same term.

The -2 and -3 suffixes are what WordPress adds when a page is duplicated, which suggests these are drafts or copies that were never cleaned up rather than deliberate variants. That is a guess and you would know better than we would.

How to verify it
  1. Open all four URLs in tabs and compare them. Confirm whether they are genuinely the same page or whether some carry content the others do not.
  2. On each one, View Page Source and search for rel="canonical". You will see each page naming itself. That is what confirms none of them is set as the primary.
  3. In Search Console, use URL Inspection on all four to see which are actually indexed and which Google has already picked as its own preferred version.
Why it matters

Right now any authority the Enduro enclosure has earned is split four ways. Consolidating puts it on one page. It also means a buyer who finds the page from a search lands on the maintained version rather than a copy nobody has updated.

What to do

Decide which URL is the real product page. Then for the two duplicate copies:

  • Set up a 301 redirect from each duplicate to the chosen primary. Rank Math → General Settings → Redirections handles this without touching any files. Use 301, not 302.
  • If you would rather keep the pages live for any reason, the softer option is to set their canonical to the primary URL instead: on each page's edit screen, Rank Math → Advanced → Canonical URL.
  • Afterwards, check that nothing in the menus or internal links still points at the retired URLs.

The one to confirm before touching: the fourth URL sits under /vpc-case-studies/. If that is a genuine case study about an Enduro install, it should stay, and the fix there is just to give it a distinct title so it stops reading as a fourth copy of the product page. We would not change that one without asking you first.

A page called "test location" is live and in the public sitemap

5 minutes Delete or noindex Reversible
What we've identified

/locations/test-location/ returns 200, has the page title test location, has no noindex tag, and is listed in the public locations sitemap. The locations sitemap contains two URLs in total, so this test page is half of it.

How to verify it
  1. Open https://www.vpcfiberglass.com/locations/test-location/ in a private browsing window, so you are seeing it as a logged-out visitor rather than as an admin.
  2. Open https://www.vpcfiberglass.com/locations-sitemap.xml and read the entries. There are two, and this is one of them.
  3. In Search Console, run URL Inspection on it to see whether Google has indexed it.
Why it matters

It is a small thing, but the locations sitemap is one of the files a search engine reads to understand where VPC physically operates. Half of it currently says "test location". Clearing it is a minute of work and it makes the remaining entry the whole signal.

What to do
  • If it is genuinely a leftover test, delete it in WordPress and empty the trash. The URL will then return 404, which is the correct answer for a page that should not exist.
  • If it needs to stay for some internal reason, open it in the editor and set Rank Math → Advanced → Robots Meta → No Index, which also removes it from the sitemap.
  • Either way, re-load locations-sitemap.xml afterwards and confirm it is gone.
5

An author archive page for a vendor admin account is indexable

5 minutes Settings only Fully reversible
What we've identified

/author/tmswebsiteadminthomasnet-com/ returns 200 and appears in the sitemap. It is a WordPress author archive, generated automatically, and its only real content is a username. That username also happens to disclose which vendor account publishes to the site.

How to verify it
  1. Open the URL in a private window and confirm it loads rather than 404s.
  2. Open https://www.vpcfiberglass.com/sitemap_index.xml, follow the author sitemap, and confirm the URL is listed there.
Why it matters

Two reasons, one minor and one worth a moment's thought. The minor one is that it is a thin page in the index that says nothing about what VPC makes. The other is that the URL itself publishes the name of an administrative account, which is information that does not need to be public.

What to do
  • Go to Rank Math → Titles & Meta → Misc Pages and turn off author archives. On a site with a single publishing account they serve no purpose, and disabling them removes the URL and drops it from the sitemap in one step.
  • If you would rather keep archives on, set author pages to noindex in the same panel instead.

If something here doesn't hold up

We would rather be corrected than be polite about it. If a verification step does not reproduce, or if one of these is the way it is on purpose and we have simply read it wrong from the outside, that is useful to know and it changes what we recommend next. Several of the things that looked like problems on other sites we have looked at turned out to be deliberate decisions once we asked.

The same goes for anything on this list you cannot change from where you sit. Knowing where the edit boundaries actually are is genuinely more useful to us than getting the fixes done quickly.
