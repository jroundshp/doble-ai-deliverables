Six items to confirm or correct

Ordered by what returns most for the time spent. Item 1 is the one worth doing first.

1

Two typos may be voiding the LocalBusiness markup

5 minutesTwo-word editFully reversible
What we found

The homepage carries three blocks of structured data. Two are clean. The third is the one stating the company name, phone and street address together, and it has two problems in its first two lines.

The context reads https://www.schema.org. The vocabulary lives at https://schema.org, without the www. And the type reads localbusiness in lower case, where schema.org type names are case sensitive and the defined type is LocalBusiness.

Why it matters

This block is the only place on the site where the name, phone and address are stated together in a form built for machines. It is what a search engine or an assistant reads to confirm VPC is a real company at a real address with a real phone number. Either error on its own can be enough for a parser to skip the block, which would mean that confirmation is simply absent. Two typos is a low price for having it work.

How to verify it
  1. Open Google's Rich Results Test, paste in https://www.vpcfiberglass.com/ and run it. Look at what it detects. If LocalBusiness is missing while the other blocks appear, that is the finding. That tool is the arbiter here, not us.
  2. Cross-check on validator.schema.org, which is more literal about the vocabulary.
  3. To see it yourself, View Page Source and search for www.schema.org. It appears once.
The correction, if you agree

Two strings change. Nothing else in the block needs touching.

Currently
{
"@context": "https://www.schema.org",
"@type": "localbusiness",
"name": "Virtual Polymer Compounds, LLC",
...
Should be
{
"@context": "https://schema.org",
"@type": "LocalBusiness",
"name": "Virtual Polymer Compounds, LLC",
...

This block is hand-placed rather than generated by the SEO plugin, so it will not be in the plugin settings. The quickest way to find it is to search the theme files or your header-injection plugin for priceRange or www.schema.org. Re-run the Rich Results Test afterwards to confirm.

2

No share image, so every shared link renders as plain text

10 minutesSettings onlyFully reversible
What we found

Most Open Graph tags are in place: og:title, og:description, og:url, og:type, og:site_name, og:locale. The one absent is og:image. There are no Twitter card tags at all.

Why it matters

VPC's sales cycle runs through email and increasingly through Teams. A link to a product page that arrives as a bare grey box is weaker than the same link carrying a photograph of the product, and the difference is one settings field. It also affects how the page is previewed anywhere else it gets shared.

How to verify it
  1. Paste https://www.vpcfiberglass.com/ into a Teams message box and wait for the preview. Do not send it. No image appears.
  2. Or View Page Source and search for og:image. You will find the other tags but not that one.
  3. Or run the URL through opengraph.xyz, which shows what each platform will render.
The correction, if you agree
  • In the SEO plugin, set a default Open Graph image under the global or social defaults. That one setting covers every page without its own.
  • Size it 1200 by 630 pixels. A photograph of finished FRP work carries further than a logo on white, since the logo usually appears alongside it anyway.
  • For pages worth a specific image, the per-page override sits in the plugin's Social tab on the edit screen.
  • Re-run the preview tool afterwards, using its refresh or re-scrape button, since platforms cache the old result.
3

Four near-identical Enduro enclosure pages, each pointing at itself

20 minutesOne judgment callReversible
What we found

Four live URLs share the title Enduro Standard Equipment Enclosure:

  • /enduro-standard-equipment-enclosure/
  • /enduro-standard-equipment-enclosure-2/
  • /enduro-standard-equipment-enclosure-3/
  • /vpc-case-studies/enduro-standard-equipment-enclosure-5/

All four return 200, all four are in the sitemaps, and each carries a canonical tag pointing at itself, so none defers to a primary. The -2 and -3 suffixes are what WordPress adds when a page is duplicated, which suggests copies that were never cleaned up rather than deliberate variants. That is a guess and you would know better.

Why it matters

Whatever authority this product has earned is currently split four ways instead of accumulating on one page. Consolidating puts it in one place, and it means a buyer arriving from a search lands on the maintained version rather than an abandoned copy.

How to verify it
  1. Open all four in tabs and compare. Confirm whether they are genuinely the same or whether some carry content the others do not.
  2. On each, View Page Source and search rel="canonical". Each names itself, which is what confirms no primary is set.
  3. In Search Console, run URL Inspection on all four to see which are indexed and which Google already prefers.
The correction, if you agree
  • Decide which URL is the real product page, then 301 the two duplicate copies to it. The SEO plugin's Redirections module handles this without touching files. Use 301, not 302.
  • If you would rather keep them live, the softer option is setting their canonical to the primary instead, on each page's edit screen.
  • Afterwards, check nothing in the menus or internal links still points at the retired URLs.
  • Confirm before touching the fourth. It sits under /vpc-case-studies/. If that is a genuine case study about an Enduro install it should stay, and the fix there is a distinct title so it stops reading as a fourth copy. We would not change that one without asking.
4

A page called "test location" is live and in the public sitemap

5 minutesDelete or noindexReversible
What we found

/locations/test-location/ returns 200, carries the title test location, has no noindex tag, and is listed in the public locations sitemap. That sitemap contains two URLs in total, so this test page is half of it.

Why it matters

The locations sitemap is one of the files a search engine reads to work out where VPC physically operates. Half of it currently says "test location". Clearing it takes a minute and makes the remaining entry the whole signal. The larger problem underneath, that a three-plant manufacturer has no real location pages at all, is in the closing section rather than here.

How to verify it
  1. Open https://www.vpcfiberglass.com/locations/test-location/ in a private window, so you see it as a logged-out visitor rather than an admin.
  2. Open https://www.vpcfiberglass.com/locations-sitemap.xml and read the entries. There are two, and this is one.
  3. In Search Console, run URL Inspection on it to see whether Google has indexed it.
The correction, if you agree
  • If it is a leftover test, delete it and empty the trash. The URL then returns 404, which is the right answer for a page that should not exist.
  • If it must stay, set it to No Index in the SEO plugin's Advanced tab, which also removes it from the sitemap.
  • Either way, reload locations-sitemap.xml afterwards and confirm it is gone.
5

An author archive is publishing an admin account name

5 minutesSettings onlyFully reversible
What we found

/author/tmswebsiteadminthomasnet-com/ returns 200 and appears in the sitemap. It is a WordPress author archive, generated automatically, and its only real content is a username.

Why it matters

Two reasons, one small and one worth a moment. The small one is that it is a thin page in the index saying nothing about what VPC makes. The other is that the URL itself publishes the name of an administrative account, which is information that does not need to be public.

How to verify it
  1. Open the URL in a private window and confirm it loads rather than returning 404.
  2. Open https://www.vpcfiberglass.com/sitemap_index.xml, follow the author sitemap, and confirm the URL is listed.
The correction, if you agree
  • In the SEO plugin, under Titles and Meta then Misc Pages, turn off author archives. On a site with a single publishing account they serve no purpose, and disabling them removes the URL and drops it from the sitemap in one step.
  • If you would rather keep archives on, set author pages to noindex in the same panel.
6

The locations page has no meta description

5 minutesOne fieldFully reversible
What we found

/locations/ carries no meta description tag at all. The homepage has one and it is well written, so this is a gap on one page rather than a site-wide habit.

Why it matters

This is the sentence under the link in search results. Left empty, the search engine writes its own from whatever text it finds, and on a page that names four facilities without linking to any of them, that sentence is unlikely to be the one you would choose. For a manufacturer whose three plants are a genuine advantage over a competitor shipping from another state, the location page is worth a written description.

How to verify it
  1. Open https://www.vpcfiberglass.com/locations/, View Page Source, and search for name="description". Nothing is returned.
  2. Compare with the homepage, where the same search finds a written description.
  3. Search Google for site:vpcfiberglass.com/locations/ and read the description it has written for you.
The correction, if you agree
  • Edit the page, open the SEO plugin panel, and write roughly 150 characters naming the plants and what they do.
  • While you are in there, it is worth spot-checking the other commercial pages for the same gap.
