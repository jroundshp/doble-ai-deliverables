Five items from the conversion

1

The phone number on the site displays one number and dials another

15 minutes New since the audit Fully reversible
What we found

On the contact page, the phone number shown to visitors is (607) 486-1483, which is correct and matches the Clubhouse Google listing. The link behind it is not that number. The text, the phone icon above it, and the whole card around them are all wired to tel:6075472767.

607-547-2767 is the number Google lists on the Rookie's Craft House profile, the one marked permanently closed. The same mismatch is in the footer, so it is on all seven pages.

The email beside it does the same thing in the other direction. The printed address is restaurant@cooperstownexperience.com, and the text links there correctly, but the envelope icon above it opens a message to rookies4850@gmail.com.

This one is new. It is not in the audit, which recorded the displayed number and did not check what the links underneath it pointed at.

Why it's important to change

On a phone, which is how most people reach a restaurant, tapping the number does not dial the number on the screen. It dials the retired brand's line. Anyone tapping to call about a team party is being routed somewhere other than where the page says they are going, and neither they nor you would have any way to notice.

We cannot tell from outside whether 607-547-2767 still rings the venue. If it does, this is untidy and nothing worse. If it has been given up along with the closed listing, then every tap-to-call from the website has been going nowhere, and the calls simply never arrive. That is the difference between a cosmetic fix and a leak, and it is why this is first on the list.

How to verify it
  1. Open https://www.cooperstownclubhouse.com/contact/ on a desktop browser. Hover over the phone number and read the destination in the status bar at the bottom of the window. It reads tel:6075472767 while the text on screen reads (607) 486-1483.
  2. Or right-click the number, copy the link address, and paste it somewhere you can read it.
  3. On a phone, tap the number and look at what appears in the dialler before you connect it.
  4. The question worth settling in the same sitting: call 607-547-2767 and find out where it rings, or whether it rings at all.
  5. Repeat the hover check on the envelope icon, which reads mailto:rookies4850@gmail.com while the text below it reads restaurant@cooperstownexperience.com.
The correction, if you agree
  1. Edit the contact page in Divi. The phone number lives in a text module inside a column, and both the module and the column carry their own click destination, which is why changing one is not enough.
  2. Check the link field in three places: the Icon module (the phone symbol), the Text module below it, and the Column containing them. In each, under Content → Link → Module Link URL, set tel:6074861483.
  3. Do the same for the envelope icon, setting it to mailto:restaurant@cooperstownexperience.com to match the text beneath it.
  4. The same pair is repeated in the site footer, which is why it appears on every page. We can see it is in the footer but not which editor controls it, so check the Divi Theme Builder footer template, the Divi Library, and the theme's own footer settings, whichever your setup uses.
  5. Save, reload the live page, and hover both again to confirm the displayed and linked values now agree.
  6. If 607-547-2767 is being given up, set call forwarding from it to the current line before it is released, and do the same with an auto-forward from the Gmail address.
2

The ORDER ONLINE menu item goes to the retired domain, and lands on a page with no ordering on it

15 minutes In the audit, clarified here Fully reversible
What we found

The audit records three homepage navigation links still pointing at the Rookie's domain, at /activities/, /contact/ and /teams/. That is accurate. Two things are worth adding to it.

First, the /contact/ one is the ORDER ONLINE item in the main menu, and because the menu is shared it appears in the header of all seven pages rather than only the homepage. Across the whole site there are 15 links to the retired domain, and this is the one on every page.

Second, following it lands on the Clubhouse contact page served from the retired domain, and that page has no online ordering on it at all. The only occurrence of the phrase anywhere on it is the menu item that sent you there.

Why it's important to change

A guest who wants to order food clicks the button that says they can, and arrives somewhere that cannot take the order. There is no error to explain it and no obvious reason for them to try again. That is a lost sale in the moment, separate from anything to do with domains.

The domain half sits underneath it. The Google listing already carries a working Order Online action, so the site is currently the weaker of the two routes to the same thing.

How to verify it
  1. Open the live homepage in a private browsing window. Hover ORDER ONLINE in the header and read the destination in the status bar. It reads rookiescrafthouseny.com.
  2. Click it and read the page you land on, to judge for yourself whether anything there can take an order.
  3. Check the header on MENU, TEAMS, CONTACT, ACTIVITIES, CAREERS and BAR MENU. The same link is in all of them.
  4. For the other two, hover the links to Activities and Teams on the homepage.
The correction, if you agree
  1. Go to Appearance → Menus and open the main header menu.
  2. The ORDER ONLINE entry is a Custom Link with an editable URL. Point it at whatever actually takes orders. If ordering is by phone today, the honest fix is to relabel it, or to remove it and let CONTACT carry that traffic.
  3. If it stays pointed at the contact page for now, at least change the domain to https://www.cooperstownclubhouse.com/contact/.
  4. Repoint the Activities and Teams links to the Clubhouse's own /activities/ and /teams/, as the audit recommends.
  5. Save and hover each one on the live site to confirm.

20 minutes New since the audit Reversible with a backup
What we found

Across the seven live pages, 21 distinct image files are referenced at addresses beginning http://rookiescrafthouseny.com/wp-content/uploads/. They include the team parties photo, the burger and beer sketches, the bartender shot, the cornhole photo and the section divider textures.

They display correctly today. This is not a visible fault on the site right now.

Why it's important to change

The audit's guidance is to keep the Rookie's domain registered and redirecting indefinitely, and we agree with that. This item is not an argument against it. It is that the live site should not be depending on it either way.

As things stand, the Clubhouse site cannot survive the retired domain going away, and that turns a domain renewal into something nobody can safely skip. The registration runs to 19 December 2026. Worth a calendar reminder regardless, but the site should be able to stand on its own before then rather than because of it. The http prefix is the smaller half, and the same edit fixes both.

Interior pages on the retired domain load rather than forward

10 minutes An upgrade, not a defect Fully reversible
What we found

The audit already established this and found the handling correct: the root redirects, and the interior pages that still load carry canonical tags pointing back to the Clubhouse. Re-verified on 17 August and unchanged. The table below is that finding in detail rather than a new one.

Address on the retired domainResponse
/301 to the Clubhouse homepage
/menu/, /bar-menu/, /teams/200, page loads, canonical to the Clubhouse
/activities/, /contact/, /careers/200, page loads, canonical to the Clubhouse
Why it's important to change

The canonical tags do the search-engine half of the job, which is why the audit treats this as handled. The gap is the human half. A canonical is a hint to a crawler and does nothing at all for a person, so someone following an old link, a bookmark or a printed flyer simply arrives on the retired domain and stays there, seeing current content under the old address with no sign anything changed.

This is the lowest-priority item here, and skipping it would be a defensible call.

How to verify it
  1. In a private window, open https://www.rookiescrafthouseny.com/menu/ and watch the address bar. It stays on the retired domain and a full menu page loads.
  2. Compare with https://www.rookiescrafthouseny.com/, which does move across. That contrast is the whole finding.
  3. View Page Source on the menu page and search for canonical to see the backstop that is already there.
The correction, if you agree
  • The aim is for every address on the retired domain to forward to the matching address on the live one, not just the homepage. If the current redirect lives in .htaccess, the rule below carries the path across.
  • If it was set with a plugin or a control-panel redirect, the same change is usually a setting worded forward with path or wildcard, rather than redirect to homepage.
  • Test with /menu/ and confirm it lands on cooperstownclubhouse.com/menu/ rather than the homepage. Sending every request to the homepage regardless of what was asked for is worse than what is there now.
Path-preserving redirect, for the retired domain
RewriteEngine On
RewriteCond %{HTTP_HOST} ^(www\.)?rookiescrafthouseny\.com$ [NC]
RewriteRule ^(.*)$ https://www.cooperstownclubhouse.com/$1 [R=301,L]

Two cautions. The RewriteCond line matters, because both domains are served by the same WordPress installation and a rule without it would redirect the live site to itself. And do item 4 before this one, or the blanket redirect will catch the image addresses the live site is still using and the images will redirect instead of loading.

6

The site blocks pinch-to-zoom on phones

2 minutes Raised in August Fully reversible
What we found

The homepage viewport tag reads width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=0. The last two values switch off pinch-to-zoom entirely. Also present on fenimorestable.com, not on cooperstownexperience.com.

Why it matters

It is a named accessibility failure, WCAG 1.4.4, and the people it affects are the ones you most want: parents and coaches reading a menu or an address on a phone between games, often outdoors in bad light. Worth saying clearly, because it was queried in August: the site is responsive. The Divi breakpoints are working. This one line is a separate setting that overrides the visitor's ability to zoom, and removing it changes nothing about the layout.

How to verify it
  1. Open the homepage on a phone and try to pinch-zoom. Nothing happens.
  2. On a desktop, View Page Source and search for user-scalable.
The correction, if you agree
  1. The tag is usually emitted by the theme or by a Divi setting rather than typed into a page. Search the theme files and any header-injection plugin for user-scalable.
  2. Delete only , maximum-scale=1.0, user-scalable=0, leaving width=device-width, initial-scale=1.0 in place.
  3. Reload on a phone and confirm pinch-zoom works.
Currently
<meta name="viewport"
      content="width=device-width, initial-scale=1.0,
               maximum-scale=1.0, user-scalable=0" />
Should be
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
7

The homepage has five H1 headings and no H2

20 minutes Raised in August Fully reversible
What we found

Five separate H1 headings on the homepage: best place for your team party, Cooperstown Clubhouse, Team Parties, activities, and CONTACT US. There are no H2 headings at all, and three H3s below them.

This one is Clubhouse-only, which is worth repeating because it was asked about in August. Fenimore's Table has one H1 and two H2s, which is correct. The complex site is also fine.

Why it matters

An H1 is the page's single statement of what it is about. Five of them is the same as none, because nothing is being distinguished from anything else, and jumping from H1 straight to H3 leaves the outline with a level missing. This is how a search engine or an assistant works out the shape of the page, and right now it reads as five unrelated top-level topics stacked on one URL.

How to verify it
  1. Open the homepage, press F12 for developer tools, and in the Console tab run document.querySelectorAll('h1').length. It returns 5. Run it again with 'h2' and it returns 0.
  2. Or View Page Source and search for <h1.
The correction, if you agree
  1. Choose which one is the real H1. Our suggestion is best place for your team party, since it says what the venue is for rather than repeating the name that is already in the logo and the title tag. That is a judgment call and it is yours.
  2. In Divi, open each of the other four heading modules and change the heading level dropdown from H1 to H2. The visual size is controlled separately in the Design tab, so nothing needs to look different afterwards.
  3. Re-run the Console check and confirm one H1 and four H2s.
8

The scrolling hiring banner is the first thing a visitor sees

5 minutes A question, not a defect Fully reversible
What we found

The homepage opens with a <marquee> element scrolling JOIN OUR TEAM TODAY repeated twelve times across the top of the page.

We are raising this as a question rather than listing it as a fault, the same way it was put in August. Hiring is clearly a real priority, and the site was edited on 6 August to add a careers page, so this may be exactly what you intend.

Why it matters

The question is whether the most valuable space on the site should be carrying a recruitment message, given that most people arriving are families and coaches looking for somewhere to eat rather than a job. Both audiences are real. Only one of them books a party.

Separately, and this part is not a judgment call: <marquee> is an obsolete HTML element. It has been formally deprecated for years, browsers keep it working out of goodwill, and screen readers handle moving text poorly. If the banner stays, it is worth rebuilding as a normal styled banner rather than a marquee.

How to verify it
  1. Load the homepage and watch the top of the page.
  2. View Page Source and search for marquee to confirm the element type.
The correction, if you agree
  1. If hiring stays on the homepage, consider moving it below the first screen so the venue introduces itself first, and link it to the careers page you already built.
  2. Replace the <marquee> with a standard Divi text or call-to-action module. Static reads better than scrolling for a single short line, and it removes the deprecated element.
  3. If the answer is that it should stay exactly as it is, that is a legitimate answer and this item can be closed.

The homepage meta description is an empty tag

5 minutes One field Fully reversible
What we found

The tag is present but carries nothing: <meta name="description" content="" />. An empty tag rather than a missing one usually means the field exists in the SEO plugin and was never filled in.

Why it matters

This is the sentence under your link in search results.   2. Do the same on the other six pages while you are there, since the same field is likely empty on all of them.
  3. This is the same underlying gap as the machine-readability row in the closing section, but this part is one field per page rather than a project.
10

14 of the 15 homepage images have no alt text

30 minutes Raised in August Fully reversible
What we found

The homepage carries 15 image tags. Fourteen have no alt attribute or an empty one. Counted on the live page on 17 August.

Why it matters

Two reasons that pull the same way. Anyone using a screen reader gets nothing from fourteen of your fifteen images, and image search has no idea what any of them show. For a venue whose appeal is visual, the food, the arcade, the cornhole, the room set up for a team, that is the part of the story machines currently cannot read at all.

How to verify it
  1. Open the homepage, press F12, and in the Console run document.querySelectorAll('img:not([alt]), img[alt=""]').length.
  2. Compare with document.querySelectorAll('img').length for the total.
The correction, if you agree
  1. In the WordPress Media Library, add an Alt Text value to each image. Setting it there carries to every place the image is used.
  2. Describe what is actually in the shot in plain words, as if to someone who cannot see it. "Team celebrating with pizza in the party room" rather than "clubhouse-photo-4".
  3. Skip purely decorative images such as the divider textures. Those are the correct use of an empty alt attribute, so one of the fifteen may legitimately stay as it is.
