How websites get built now

A plain guide to where web development stands in 2026, how it got here, and how the newer approach compares with WordPress, Wix and Squarespace. You run WordPress sites every day, so it starts from what you already know.

01The short version

WordPress still runs about 40% of all websites, and it remains a reasonable choice for plenty of businesses. Professional developers starting a new site, though, have mostly moved to a different approach. The site is built with a framework such as Next.js or Astro, staff edit content in a separate dashboard, and finished pages are served from a worldwide network.

Built that way, a site loads faster and has far fewer parts to patch, and the business owns every piece of it outright. The catch is that the editing dashboard has to be set up on purpose. With WordPress it comes in the box.

02If you know WordPress, you know most of this

Almost every part of a WordPress site has an equivalent in the newer approach. Mostly the names change, along with where each piece lives.

In WordPressIn the newer approachWhat changes
wp-adminA content dashboard (Sanity, Payload, Storyblok)It does the same job: log in and edit text, photos, products and data sheets. It sits apart from the site's code, so a content edit can't break the layout.
Custom fields (ACF)Content modelsFields like flow rate, dimensions or a data sheet link are designed into the dashboard from day one, with a field for each product spec.
ThemeComponentsA header or product card is built once and used everywhere. Change it once and every page updates.
PluginsCode libraries, added by the developerA new feature is added to the code and tested on a preview before it goes live, instead of being switched on in the live admin.
Yoast / Rank MathBuilt into the siteTitles, descriptions and schema are generated from the same product data as the page, so the page and what Google reads can't drift apart.
Hosting and a caching layerVercel, Netlify or CloudflarePages are built ahead of time and served from the location nearest the visitor. There's no cache to purge after an edit.
Revisions and a backup pluginVersion history (Git)Every change to the site is recorded with who made it and when. Each one gets its own preview link, and any of them can be undone in one step.

03The four ways sites get built today

Share of all websites, W3Techs, 22 September 2026: WordPress 40.2% · Shopify 5.4% · Wix 4.2% · Squarespace 2.4% · Webflow 0.8% · no tracked system 31.5%

Rent it

Website builders: Wix, Squarespace, Square Online, Webflow, Framer

You pay a monthly fee and edit visually in the browser. Hosting, security and updates are the platform's job. Webflow and Framer are the builders designers currently prefer.

Strengths
  • Easiest to start and to edit
  • Nothing to patch or host
Weaknesses
  • You rent the site; the design and features don't come with you if you leave
  • You get only the features the platform offers
  • Limited control over technical search setup
Assemble it

WordPress, with a theme and plugins

The site lives in a database on a server, and each page is assembled when someone visits. Features come from plugins, each written by a different company. WordPress holds 58.8% of sites that use a known content system. Its share of all websites peaked at 43.6% in mid-2025 and has slipped to 40.2% since.

Strengths
  • Huge ecosystem; a plugin exists for almost anything
  • Familiar dashboard, and WordPress help is easy to find
  • Good fit for large amounts of content edited by a team
Weaknesses
  • Every plugin is another company's code running on your site
  • 11,334 new security holes found in 2025, up 42%; 91% were in plugins
  • Constant updates, and plugins can conflict with each other
  • Speed depends on the theme, the plugins and the host
Build it

Modern frameworks: Next.js, Astro

The site is written as code, built into finished pages ahead of time, and served from a global network. Next.js is the most widely used: 21.5% of developers in Stack Overflow's 2025 survey, and still rising. Astro is built specifically for content sites. Cloudflare bought the company behind it in January 2026 and kept it open source.

Strengths
  • Fast by default
  • No database or plugins exposed to attack
  • Full control over design, schema and search setup
  • Standard code; it moves between hosts without a rewrite
Weaknesses
  • Structural changes need a developer
  • No editing dashboard until you add one
  • Fewer off-the-shelf add-ons; features get built
  • The framework needs updates too (two serious security fixes in 2025)
Edit it

Content dashboards: Sanity, Payload, Storyblok, Contentful

This is the piece that gives a framework site its login. Your team edits products, pages and photos in a dashboard, and the site rebuilds itself with the change. The newer ones show a live preview of the page as you type.

Strengths
  • WordPress-style editing, without WordPress running the site
  • Content can feed more than one place: website, printed catalog, AI tools
Weaknesses
  • One more account to own
  • Depending on team size, one more subscription
  • Has to be designed around your content at the start

04How we got here

  • Late 1990sHand-written pages. A developer edited files and uploaded them. There was no dashboard, no history and no undo. This is the real "old school," and it's what "built in code" can sound like from the outside.
  • 2003WordPress launches and gives business owners a login. It's a big step forward, and it brings along a server, a database and plugins that all need looking after.
  • 2004–2013Hosted builders arrive: Squarespace, Wix, Shopify, then Webflow. Websites become a subscription, easy to start and hard to leave.
  • 2013–2016Facebook releases React; Next.js follows in 2016. Pages start being built ahead of time and served from global networks, and editing moves into separate dashboards.
  • 2020sFrameworks become the default for professional builds. WordPress stays the biggest platform, but its share starts slipping after a mid-2025 peak.
  • 2025–2026AI changes both ends. Developers build with AI assistants, and customers increasingly find businesses by asking ChatGPT, Google's AI Overviews or Perplexity.

05The techniques that define current practice

  • Pages are built ahead of time. Nothing is assembled while the visitor waits, and every page comes from a server near them.
  • A product card, spec table or quote form is built once as a component and reused, so a fix in one place is a fix everywhere.
  • Content is kept apart from design. Staff change words and photos, developers change how things look and work, and neither can break the other's side.
  • Each edit gets its own preview link before it goes live, and the full history stays with the site.
  • Photos are resized automatically for each screen. On a site we launched this month, turning this on cut the homepage from 6.3 MB to 0.9 MB and raised Google's mobile speed score from 67 to 96.
  • One set of product specs feeds the page, the schema Google reads and the files AI tools read. A corrected figure is corrected everywhere at once.
  • AI is now part of the job: 84% of developers use or plan to use AI tools (Stack Overflow, 2025). These tools work best on code-based sites, where the whole site sits in one readable place. On WordPress, the same information is spread across database settings, theme options and plugin screens.

06Where it's heading

The biggest change is where buyers start. More of them ask ChatGPT or Google's AI Overview before they ever click a link, and those tools lean on sites with clean structure and accurate product data. For a company that sells on specifications, that matters more than any design trend.

The newer dashboards are also adding visual, edit-on-the-page tools, so editing a framework site is starting to feel like editing in WordPress. And the large infrastructure companies are putting money behind these frameworks: Vercel backs Next.js, and Cloudflare now owns Astro.

WordPress will be around for a long time. It's losing ground slowly, from 43.6% of the web to 40.2% in about fifteen months.

07What if the person who built it isn't around?

This question applies to every platform, WordPress included. The answer depends less on the technology than on two things: who holds the keys, and whether the setup is written down.

Whoever builds your site, us included, you should expect five things:

  1. The domain, registered in the company's own account.
  2. The hosting account, owned by the company, with the builder added as a member.
  3. The code, in a repository the company owns, with a plain-English guide to editing and publishing.
  4. Dashboard logins for the people who edit content day to day.
  5. A written list of every account and where its login is kept.

With those in place, a framework site is one of the easier things to hand over. Next.js is one of the most common skills in web development. The entire site and its full history sit in one place. A new developer, or an AI assistant, can read the whole thing and work out how it fits together.

WordPress raises the same question in a different form: who holds the admin login, the hosting account, and the licenses for the paid theme and plugins. Those are often set up under whoever built the site, which is worth checking on any WordPress site you manage.

08The line between what you edit and what a developer edits

Every setup has one. Having a login doesn't remove the need for a developer. It decides where the line falls.

You editA developer handles
WordPress with an agencyPages, text, photos, product fields, SEO titlesPlugins, theme changes, schema, server and caching
Framework with a content dashboardPages, text, photos, product fields, SEO titlesComponents, new features, integrations, schema
Website builderAlmost everything the platform allowsNothing, but anything the platform doesn't offer can't be done

InterActive Play works like the first row. You make content changes yourself and they go live right away, while the schema plugin and theme work go through the agency. A well-built framework site with a dashboard puts the line in the same place for your team. The differences show up on the developer's side: how fast a change can be made, how safely it can be tested first, and how easily someone new could pick it up.

09What leading developers recommend, and when

SituationUsual recommendation
New business site where speed, Google and AI visibility matter, with a developer relationshipA framework (Next.js or Astro) plus a content dashboard, on Vercel, Netlify or Cloudflare
Small team, no developer, wants to do everything visuallyWebflow or Framer; Squarespace or Wix for the simplest sites
Large existing WordPress site, a team fluent in it, and real dependence on specific pluginsStay on WordPress, keep plugins to a minimum, use a good host
Online storeShopify

Our view: for a new site, the framework approach wins on speed, security and search, and the dashboard closes most of the editing gap. For a big WordPress site that works and a team that knows it well, switching only makes sense when the plugin upkeep or the speed starts costing you something.
